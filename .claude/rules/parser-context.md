# Project context

Rust parser that turns raw [Retrosheet](https://www.retrosheet.org/) event/box-score files into structured CSVs (and optionally JSONL). Downstream, those CSVs are converted to Parquet and consumed by the `baseball.computer` SQLMesh project. Retrosheet's event format is a stateful text format — the parser maintains full per-game state (lineup, runners, outs, score) to derive every output column.

**Status (2026-10-12):** Active. The parser reads a Corpus revision from [droher/retrosheet-mirror](https://github.com/droher/retrosheet-mirror): a tag per revision on its `main`, from which `mirror materialize --revision` builds the corpus out of the mirror's GitHub Release assets (`2026.08-c2` is the August 2026 Retrosheet Release plus our Corrections; `2026.08-c1` is the same tree from before the mirror dropped its data branches). `CORPUS_REVISION` pins the revision CI builds. The mirror owns every download from Retrosheet and Lahman and every Correction to that data (restored files, single-line patches, the NLB box-score rules, and the reviewed whole-game replacements); this repo no longer fetches or patches the corpus. Full corpus at `2026.08-c1` = 208,694 PBP games / 18.37M events plus 223,189 box-score games. ~1,926 games have no `info,number` (mostly box-score doubleheaders before 1920), for which `reconcile_with_game_id` (in `event_file/game_state.rs`) uses the game ID suffix. The parser rejects games that list one player twice in a side's starting lineup (players who move slots mid-game are accepted). Pitch lexing in `src/event_file/pitch_sequence.rs` preserves all period-separated segments and resumption catcher-pickoff metadata. `GameState` resolves exact pitch identities across each appearance, reconciles compatible annotations, and quarantines explicitly reviewed conflicts; unexpected conflicts fail the export. See `docs/pitch_sequence_pa_resume.md` for matching, validation, and regeneration requirements. The `info`-value trim is scoped to known string-typed fields (team/site/scorer/inputter/translator/wp/lp/save/gwrbi/umps); strict-parsed fields (date, numbers, bool, enum lookups) keep their original strict behavior so corrupt structured values still fail loudly. The legacy parser is the long-lived implementation — no rewrite in flight.

**Findings:** every data problem the parser warns about carries a `kind` field and is also written to `findings.csv` in the output root (`source,kind,game_id,file,line,message`; `file` is relative to the corpus root, such as `retrosheet/ngl_b/1926.EBR`). The parser never fails on a finding. The mirror's release session triages the file with `mirror findings triage`, which is the gate; known cases (duplicate NLB games, pitcher responsibility for a missing runner, game ID and `info` disagreements, missing `info,number`) are recorded as Findings there. A new warning that is a data problem needs a `kind`; operational warnings stay kind-less.

Output Parquet files are published to Cloudflare R2 (`s3://timeball/event`, `misc`, `biodata`, `baseballdatabank`) on a manual publish run only, and feed `droher/baseball.computer`.
