# Project context

Rust parser that turns raw [Retrosheet](https://www.retrosheet.org/) event/box-score files into structured CSVs (and optionally JSONL). Downstream, those CSVs are converted to Parquet and consumed by the `baseball.computer` dbt pipeline. Retrosheet's event format is a stateful text format — the parser maintains full per-game state (lineup, runners, outs, score) to derive every output column.

**Status (2026-10-07):** Active. Legacy parser runs cleanly on current Retrosheet corpus (assembled by `bin/fetch_retrosheet.py` from retrosheet.org per-year + bundle URLs; the older `alldata.zip` workflow is deprecated since the published bundle lags by months). The fetch restores files Retrosheet has dropped from `corpus_overrides/` (currently the 1871/1872/1874 box-score files, whose per-year zips now ship only `TEAM` files) and exits nonzero when any per-year box zip yields no box file and has no override. Full corpus after the October 2026 release = 208,694 PBP games / 18.37M events plus 223,189 box-score games. Known WARNs: six internal NLB box-file dupes in `1913.EBR`/`1926.EBR`; two identical NLB PBP dupes (CI2194308030, NY6194505230); four pitcher-responsibility-for-non-existent-runner cases (`riege101`, `willv101`, `steeb102`, `oescj101`); HOM194307080 whose ID and `info,hometeam` disagree; HOM194509200 whose ID and `info,number` disagree; ~1,926 games with no `info,number` (mostly box-score doubleheaders before 1920), for which `reconcile_with_game_id` (in `event_file/game_state.rs`) uses the game ID suffix. `uv run python bin/patch_known_corpus_bugs.py <retrosheet_dir>` must run after every fresh fetch: it applies the single-game `PATCHES` in that script (some are now no-ops because Retrosheet fixed them upstream) and then `bin/ngl_box_corrections.py`, which applies rule-based corrections to `ngl_b/*.EBR` (736 records in the October 2026 release) and warns on 21 records it cannot resolve; the parser drops those 21 with `ERROR` logs. The parser rejects games that list one player twice in a side's starting lineup (players who move slots mid-game are accepted); 12 more NLB box-score games parse but contradict themselves and are excluded from the `baseball.computer` release build. See [docs/corpus_corrections.md](docs/corpus_corrections.md) and the full list in `docs/ngl_box_corrections.csv`. Pitch lexing in `src/event_file/pitch_sequence.rs` preserves all period-separated segments and resumption catcher-pickoff metadata. `GameState` resolves exact pitch identities across each appearance, reconciles compatible annotations, and quarantines explicitly reviewed conflicts; unexpected conflicts fail the export. see `docs/pitch_sequence_pa_resume.md` for matching, validation, and regeneration requirements. The `info`-value trim is scoped to known string-typed fields (team/site/scorer/inputter/translator/wp/lp/save/gwrbi/umps); strict-parsed fields (date, numbers, bool, enum lookups) keep their original strict behavior so corrupt structured values still fail loudly. The legacy parser is the long-lived implementation — no rewrite in flight.

Upstream raw data is fetched directly from retrosheet.org via `bin/fetch_retrosheet.py` (see Build/run section). Output Parquet files are published to Cloudflare R2 (`s3://timeball/event`, `s3://timeball/misc`) and feed the dbt project at `droher/baseball.computer`.
